# Key Radar Signal Processing Concepts

This document tracks the key concepts introduced during this project and points to the relevant MATLAB files where they are implemented.

| Concept | Description | Implemented In |
| :--- | :--- | :--- |
| **Data Cube** | A 2D matrix structuring raw 1D signal data into `fast-time` (range) and `slow-time` (Doppler) dimensions for radar processing. | `loadIQData.m` |
| **Coherent Processing Interval (CPI) in Passive Radar** | In passive radar, there are no transmitted pulses. The CPI is an **artificial construct** created by segmenting the continuous incoming data stream into fixed-length chunks. Each chunk is treated as a "virtual pulse," allowing for Doppler processing. The length of this artificial CPI is a critical tuning parameter: a longer CPI improves Doppler resolution but can cause smearing for fast targets, while a shorter CPI has worse Doppler resolution but provides a clearer snapshot. | `analyzeBistaticData.m` (see `config.cpi_duration_s`) |
| **Reference Spectrum and Pilot-Evidence Precheck** | A short-slice diagnostic that confirms the reference channel looks like a usable ATSC illuminator by checking ADC level, spectral flatness, a metadata-anchored pilot PSD line, and whether the resulting reference is sufficient to continue passive-radar analysis. This is especially relevant for passive HDTV because the ATSC pilot is the one narrow, always-transmitted spectral feature that reliably tells us whether the direct-path reference is present at the expected broadcast location. The pass/fail gate is now PSD-first, not coherence-first. | `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/checkRefQuality.m`, `BistaticDataAnalysis/helperMeasureATSCPilotEvidence.m`, `BistaticDataAnalysis/helperMeasurePilotCoherenceProfile.m` |
| **ATSC Pilot Evidence Audit** | A pilot-identification step that uses one centered Welch PSD for both plotting and scoring, anchors the expected pilot to the ATSC raster and capture tune frequency, searches the normal-side neighborhood first, keeps mirrored candidates diagnostic-only, and then measures residual pilot stability after frequency centering. In this bistatic passive HDTV workflow that matters because the reference channel drives direct-path lag calibration and ECA-C clutter cancellation, so confirming the real transmitted pilot is more meaningful than rewarding whichever FFT bin happened to stay phase-aligned across CPIs. The old FFT-bin coherence metric remains available only as a legacy diagnostic. | `BistaticDataAnalysis/helperMeasureATSCPilotEvidence.m`, `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/runATSCPilotAuditValidation.m`, `BistaticDataAnalysis/tests/ATSCPilotAuditTest.m` |
| **Direct-Path Lag Dominance Check** | A lag-domain precheck that uses a whitened cross-correlation across multiple CPIs to verify that the surveillance and reference channels share one dominant direct-path delay instead of a flat or ambiguous lag profile. | `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/helperMeasureCrossCorrelationPeak.m` |
| **Zero-Doppler Ridge Suppression Check** | A before/after ECA-C diagnostic that measures whether the direct-path and static-clutter ridge is strong before mitigation and then driven down toward the noise floor after ECA-C. | `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/helperMeasureZeroDopplerSuppression.m`, `BistaticDataAnalysis/mitigateClutter.m`, `BistaticDataAnalysis/createRDM.m` |
| **Session RF Sufficiency Audit** | A session-level pre-detector audit that runs the direct-path precheck across multiple packaged-session parts, checks reference quality, direct-path lag stability, pilot-frequency consistency, and both zero-Doppler suppression depth and residual post-ECA ridge level, then decides whether the capture is sufficient for `aircraft_detection` or the stricter `tracking_validation` goal. It de-emphasizes raw inter-channel power asymmetry when surveillance and reference hardware have intentionally different gain, and it treats a reference-side LNA/preamplifier as a valid hardware adjustment when PSD-based pilot evidence is persistently weak. | `BistaticDataAnalysis/runSessionRFQualityAudit.m`, `BistaticDataAnalysis/summarizeRFQualityAudit.m`, `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/test_rfQualityAudit.m` |
| **Visualization Profiles for Graphics Stability** | The packaged-session wrapper and the standalone analysis script now resolve one shared graphics profile so the high-value views stay available while the higher-risk `uifigure` / `geoglobe` paths and legacy per-part figure fan-out can be disabled by default. The analysis also returns a figure inventory, ranked crash hypotheses, and fast restart commands that reuse saved truth or detector snapshots instead of rerunning the full IQ chain after a sync. | `BistaticDataAnalysis/helperResolveVisualizationProfile.m`, `BistaticDataAnalysis/runBistaticAnalysisSession.m`, `BistaticDataAnalysis/analyzeBistaticData.m`, `BistaticDataAnalysis/helperBuildSessionRestartCommands.m`, `BistaticDataAnalysis/render_rdm_part.m` |
| **Toolbox TDOA Measurement Refinement** | An offline timing-only evaluation path that keeps the existing detector context but re-measures each detection's delay with `phased.TDOAEstimator` after direct-path suppression and Doppler compensation. This compares toolbox delay estimation against the current CAF-derived range measurement without changing localization or truth scoring. | `BistaticDataAnalysis/helperEstimateToolboxTDOARange.m`, `BistaticDataAnalysis/helperApplyToolboxTDOARefinement.m`, `BistaticDataAnalysis/runOfflineToolboxBenchmark.m` |
| **Toolbox CFAR Parity Wrapper** | A replay-stage comparison path that swaps the custom CFAR core for `phased.CFARDetector2D` while preserving the passive-radar-specific wrapper logic around it: notch fill, ATSC ghost-range penalties, minimum-SNR gating, and local-max suppression. | `BistaticDataAnalysis/detectTargetsToolboxCFAR2D.m`, `BistaticDataAnalysis/helperRunDetectorReplayVariant.m`, `BistaticDataAnalysis/runOfflineToolboxBenchmark.m` |
| **Offline Variant Benchmark Harness** | A benchmark entrypoint that runs `custom_baseline`, `toolbox_tdoa`, `toolbox_cfar`, and `toolbox_tdoa_cfar` on the same replay input and reports runtime per stage, total runtime, detection count, TP/FA/miss, mean Pd, and deltas versus the baseline. | `BistaticDataAnalysis/runOfflineToolboxBenchmark.m`, `BistaticDataAnalysis/plotOfflineToolboxBenchmarkSummary.m` |
| **System Composer Pipeline Quick Reference** | A lightweight logical architecture that shows the main packaged-session analysis path, the ADS-B truth-alignment branch, and the saved-artifact replay paths for truth diagnostics and detector sweeps. It is a handoff/orientation diagram, not an executable Simulink processing chain. | `BistaticDataAnalysis/architecture/buildBistaticAnalysisArchitecture.m`, `BistaticDataAnalysis/architecture/bistaticAnalysisQuickReference.slx`, `BistaticDataAnalysis/architecture/bistaticAnalysisQuickReference.png` |
