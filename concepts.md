# Key Radar Signal Processing Concepts

This document tracks the key concepts introduced during this project and points to the relevant MATLAB files where they are implemented.

| Concept | Description | Implemented In |
| :--- | :--- | :--- |
| **Data Cube** | A 2D matrix structuring raw 1D signal data into `fast-time` (range) and `slow-time` (Doppler) dimensions for radar processing. | `loadIQData.m` |
| **Coherent Processing Interval (CPI) in Passive Radar** | In passive radar, there are no transmitted pulses. The CPI is an **artificial construct** created by segmenting the continuous incoming data stream into fixed-length chunks. Each chunk is treated as a "virtual pulse," allowing for Doppler processing. The length of this artificial CPI is a critical tuning parameter: a longer CPI improves Doppler resolution but can cause smearing for fast targets, while a shorter CPI has worse Doppler resolution but provides a clearer snapshot. | `analyzeBistaticData.m` (see `config.cpi_duration_s`) |
| **Reference Spectrum and Pilot-Coherence Precheck** | A short-slice diagnostic that confirms the reference channel looks like a usable ATSC illuminator by checking ADC level, broadband spectral shape, and the strength of the coherent pilot tone before full passive-radar processing. | `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/checkRefQuality.m`, `BistaticDataAnalysis/helperMeasurePilotCoherenceProfile.m` |
| **ATSC Pilot Geometry-Aware Selection** | A pilot-identification step that separates the strongest coherent spectral line from the physically plausible ATSC pilot by using the capture LO offset, the SDR tune frequency, the 6 MHz ATSC channel raster, and the local narrow-line prominence in the spectrum. It also compares mirrored and non-mirrored candidates to expose likely spectral inversion. | `BistaticDataAnalysis/helperSelectATSCPilotCandidate.m`, `BistaticDataAnalysis/checkRefQuality.m`, `BistaticDataAnalysis/runDirectPathPrecheck.m` |
| **Direct-Path Lag Dominance Check** | A lag-domain precheck that uses a whitened cross-correlation across multiple CPIs to verify that the surveillance and reference channels share one dominant direct-path delay instead of a flat or ambiguous lag profile. | `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/helperMeasureCrossCorrelationPeak.m` |
| **Zero-Doppler Ridge Suppression Check** | A before/after ECA-C diagnostic that measures whether the direct-path and static-clutter ridge is strong before mitigation and then driven down toward the noise floor after ECA-C. | `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/helperMeasureZeroDopplerSuppression.m`, `BistaticDataAnalysis/mitigateClutter.m`, `BistaticDataAnalysis/createRDM.m` |
| **Session RF Sufficiency Audit** | A session-level pre-detector audit that runs the direct-path precheck across multiple packaged-session parts, checks reference quality, direct-path lag stability, pilot-frequency consistency, and both zero-Doppler suppression depth and residual post-ECA ridge level, then decides whether the capture is sufficient for `aircraft_detection` or the stricter `tracking_validation` goal. It de-emphasizes raw inter-channel power asymmetry when surveillance and reference hardware have intentionally different gain, and it treats a reference-side LNA/preamplifier as a valid hardware adjustment when pilot coherence is persistently weak. | `BistaticDataAnalysis/runSessionRFQualityAudit.m`, `BistaticDataAnalysis/summarizeRFQualityAudit.m`, `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/test_rfQualityAudit.m` |
| **Seed-Backed Passive HDTV Session Synthesis** | A synthetic-session path that loads a captured or probe HDTV baseband seed, normalizes it to a stable RMS level, keeps the full seed in the reference and direct-path channels, and packages a traceable dual-channel `.bb` session plus truth. The current workflow is explicitly an intermediate development model: the recommended dataset mode uses conditioned target echoes, while a full-seed comparison mode remains available for artifact studies. | `SyntheticHDTVSimulation/buildSyntheticHDTVBaselineScenarioConfig.m`, `SyntheticHDTVSimulation/helperSyntheticCreateProbeSeed.m`, `SyntheticHDTVSimulation/helperSyntheticLoadSeedWaveform.m`, `SyntheticHDTVSimulation/helperSyntheticSynthesizeSeedBackedChannels.m`, `SyntheticHDTVSimulation/generateSyntheticHDTVSession.m`, `SyntheticHDTVSimulation/seedBackedSyntheticHDTVSessionWalkthrough.m` |
| **Capture-Backed Truth Bundle Normalization** | When the seed source resolves to a packaged capture session with ADS-B, the synthetic workflow can switch from waypoint-authored truth to capture-backed truth. The helper resolves the full session context, clips ADS-B to the selected radar window, projects the tracks into bistatic measurement space, aligns them to the generator timeline, filters retained aircraft with auditable reasons, and returns the same normalized `truth_bundle` contract used by the synthetic waypoint path. | `SyntheticHDTVSimulation/buildSyntheticHDTVBaselineScenarioConfig.m`, `SyntheticHDTVSimulation/helperSyntheticResolveSessionContext.m`, `SyntheticHDTVSimulation/helperSyntheticBuildCaptureTruthBundle.m`, `SyntheticHDTVSimulation/helperSyntheticGenerateTruth.m`, `SyntheticHDTVSimulation/helperSyntheticBuildManifest.m` |
| **Range-Only Echo Gain Heuristic** | Capture-backed targets currently receive amplitude from a deterministic range-only heuristic rather than a detailed scattering model. The generator computes `echo_gain_db` from the median total bistatic path length over the selected window, records the chosen `echo_gain_policy` in truth metadata, and reuses that metadata during echo synthesis and manifesting so downstream validation sees the same gain contract the generator used. | `SyntheticHDTVSimulation/helperSyntheticBuildCaptureTruthBundle.m`, `SyntheticHDTVSimulation/helperSyntheticSynthesizeToolboxTargetEchoes.m`, `SyntheticHDTVSimulation/helperSyntheticSynthesizeSeedBackedChannels.m`, `SyntheticHDTVSimulation/helperSyntheticBuildManifest.m`, `SyntheticHDTVSimulation/helperSyntheticWriteBasebandParts.m` |
| **Toolbox-Native Wideband Target Echo Synthesis** | The primary readiness path now maps bistatic excess-range and Doppler truth into `phased.WidebandFreeSpace` so the synthetic target echoes are generated with a toolbox-native wideband propagation analogue instead of a fully custom delay/Doppler synthesizer. The helper compensates propagation latency before writing the target-return waveform back into the surveillance channel. | `SyntheticHDTVSimulation/helperSyntheticSynthesizeToolboxTargetEchoes.m`, `SyntheticHDTVSimulation/helperSyntheticSynthesizeSeedBackedChannels.m`, `SyntheticHDTVSimulation/buildSyntheticHDTVBaselineScenarioConfig.m` |
| **Conditioned Echo-Source Seed Replay** | The recommended intermediate algorithm-test dataset suppresses the strongest pilot-like narrowband line in a second seed copy before echo synthesis. That conditioning reduces the severity of truth-aligned Doppler-column artifacts relative to the full-seed comparison dataset, while keeping the reference and direct-path channels on the original seed. | `SyntheticHDTVSimulation/buildSyntheticHDTVBaselineScenarioConfig.m`, `SyntheticHDTVSimulation/helperSyntheticBuildConditionedEchoSeed.m`, `SyntheticHDTVSimulation/helperSyntheticSynthesizeSeedBackedChannels.m`, `SyntheticHDTVSimulation/helperSyntheticBuildManifest.m`, `SyntheticHDTVSimulation/helperSyntheticWriteBasebandParts.m`, `SyntheticHDTVSimulation/seedBackedSyntheticHDTVSessionWalkthrough.m`, `SyntheticHDTVSimulation/helperSyntheticDescribeTargetEchoDatasetMode.m` |
| **Walkthrough-Editable Synthetic Scenario Knobs** | The synthetic HDTV walkthrough exposes capture duration, repetition cadence, truth sample period, and an explicit waypoint-based `targets` struct array as first-class user knobs. The walkthrough applies those edits directly to the baseline scenario config, prints a target start/end summary, previews the resulting site geometry and bistatic truth, and then generates artifacts whose manifest and saved truth match the edited scenario. | `SyntheticHDTVSimulation/seedBackedSyntheticHDTVSessionWalkthrough.m`, `SyntheticHDTVSimulation/helperSyntheticSummarizeScenarioConfig.m`, `SyntheticHDTVSimulation/helperSyntheticPlotScenarioOverview.m` |
| **ADS-B-To-Globe Truth Preview** | The walkthrough can now render retained capture-backed aircraft on the same `trackingGlobeViewer` preview used for synthetic waypoint truth. Because the globe preview consumes sampled `truth_bundle.targets`, the 3-D lines, Tx/Rx markers, and endpoint markers match the exact aircraft timeline that later drives RF synthesis and manifest metadata. | `SyntheticHDTVSimulation/helperSyntheticPlotTruthGlobePreview.m`, `SyntheticHDTVSimulation/seedBackedSyntheticHDTVSessionWalkthrough.m`, `SyntheticHDTVSimulation/helperSyntheticSummarizeScenarioConfig.m`, `SyntheticHDTVSimulation/tests/SyntheticHDTVCaptureTruthTest.m` |
| **TrackingGlobeViewer Synthetic Truth Context** | A 3-D globe preview that renders the exact sampled synthetic truth trajectories used for delay and Doppler synthesis, overlays Tx/Rx site markers plus per-target start/end markers, and captures a stable snapshot for the walkthrough. It complements the 2-D overview by showing whether the aircraft truth sits where expected in Earth context before IQ generation. | `SyntheticHDTVSimulation/helperSyntheticPlotTruthGlobePreview.m`, `SyntheticHDTVSimulation/seedBackedSyntheticHDTVSessionWalkthrough.m`, `SyntheticHDTVSimulation/tests/SyntheticHDTVSessionGeneratorTest.m` |
| **Question-Driven Synthetic Validation Walkthrough** | A plain-text MATLAB live script that treats one synthetic-session run as a validation report. It frames the run as explicit questions, surfaces scenario, artifact, readiness, and downstream truth-match numbers in tables, and pairs the packaged-session replay with the newer detection-vs-truth diagnostics instead of relying only on the legacy track-comparison plot for interpretation. | `SyntheticHDTVSimulation/seedBackedSyntheticHDTVSessionWalkthrough.m`, `BistaticDataAnalysis/runBistaticAnalysisSession.m`, `BistaticDataAnalysis/analyzeBistaticData.m`, `BistaticDataAnalysis/runDetectionTruthDiagnostics.m` |
| **Session-Level Signal-Physics Readiness Gate** | A post-generation readiness gate that reads one generated synthetic session back, validates every packaged radar part against the truth that drove synthesis, checks packaging integrity, seed preservation, fractional direct-path lag, target delay/Doppler placement, target-strength ordering, and vertical Doppler-column rejection, and then writes a structured pass/fail summary back into the session manifest. That summary now also records whether the session is the recommended conditioned target-echo dataset or a full-seed comparison dataset. | `SyntheticHDTVSimulation/helperSyntheticValidateGeneratedIQ.m`, `SyntheticHDTVSimulation/helperSyntheticValidateGeneratedIQPart.m`, `SyntheticHDTVSimulation/seedBackedSyntheticHDTVSessionWalkthrough.m`, `SyntheticHDTVSimulation/helperSyntheticBuildManifest.m`, `SyntheticHDTVSimulation/tests/SyntheticHDTVSessionGeneratorTest.m` |
| **Seed Fixture Provenance And Readiness Manifesting** | Each generated session now records which seed fixture drove the synthesis, which echo-generation model was used, which target-echo dataset mode was selected, whether a full-seed comparison run was requested, and the latest readiness-check result. The same provenance is also preserved in the saved `scenario_truth.mat` artifact so manifest-only revalidation can recover the signal-physics context. | `SyntheticHDTVSimulation/helperSyntheticDescribeSeedFixture.m`, `SyntheticHDTVSimulation/helperSyntheticBuildManifest.m`, `SyntheticHDTVSimulation/generateSyntheticHDTVSession.m`, `SyntheticHDTVSimulation/helperSyntheticValidateGeneratedIQ.m`, `SyntheticHDTVSimulation/helperSyntheticDescribeTargetEchoDatasetMode.m` |
| **Local CAF Prominence And Truth-Doppler Column Rejection** | The readiness validator still reports a per-target local CAF prominence metric from the post-ECA-C RDM, and the truth-aligned full-height Doppler-column check remains an explicit readiness-failure mechanism. In the current intermediate workflow, conditioned target echoes reduce the severity of the column artifact relative to the full-seed comparison dataset, but they do not eliminate it. These metrics are still interpretive signal-quality measures, not calibrated RF link-budget outputs. | `SyntheticHDTVSimulation/helperSyntheticValidateGeneratedIQ.m`, `SyntheticHDTVSimulation/helperSyntheticValidateGeneratedIQPart.m`, `SyntheticHDTVSimulation/tests/SyntheticHDTVSessionGeneratorTest.m` |
