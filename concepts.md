# Key Radar Signal Processing Concepts

This document tracks the key concepts introduced during this project and points to the relevant MATLAB files where they are implemented.

| Concept | Description | Implemented In |
| :--- | :--- | :--- |
| **Data Cube** | A 2D matrix structuring raw 1D signal data into `fast-time` (range) and `slow-time` (Doppler) dimensions for radar processing. | `loadIQData.m` |
| **Coherent Processing Interval (CPI) in Passive Radar** | In passive radar, there are no transmitted pulses. The CPI is an **artificial construct** created by segmenting the continuous incoming data stream into fixed-length chunks. Each chunk is treated as a "virtual pulse," allowing for Doppler processing. The length of this artificial CPI is a critical tuning parameter: a longer CPI improves Doppler resolution but can cause smearing for fast targets, while a shorter CPI has worse Doppler resolution but provides a clearer snapshot. | `analyzeBistaticData.m` (see `config.cpi_duration_s`) |
| **Reference Spectrum and Pilot-Coherence Precheck** | A short-slice diagnostic that confirms the reference channel looks like a usable ATSC illuminator by checking ADC level, broadband spectral shape, and the strength of the coherent pilot tone before full passive-radar processing. | `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/checkRefQuality.m`, `BistaticDataAnalysis/helperMeasurePilotCoherenceProfile.m` |
| **ATSC Pilot Geometry-Aware Selection** | A pilot-identification step that separates the strongest coherent spectral line from the physically plausible ATSC pilot by using the capture LO offset, the SDR tune frequency, the 6 MHz ATSC channel raster, and the local narrow-line prominence in the spectrum. It also compares mirrored and non-mirrored candidates to expose likely spectral inversion. | `BistaticDataAnalysis/helperSelectATSCPilotCandidate.m`, `BistaticDataAnalysis/checkRefQuality.m`, `BistaticDataAnalysis/runDirectPathPrecheck.m` |
| **Direct-Path Lag Dominance Check** | A lag-domain precheck that uses a whitened cross-correlation across multiple CPIs to verify that the surveillance and reference channels share one dominant direct-path delay instead of a flat or ambiguous lag profile. | `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/helperMeasureCrossCorrelationPeak.m` |
| **Zero-Doppler Ridge Suppression Check** | A before/after ECA-C diagnostic that measures whether the direct-path and static-clutter ridge is strong before mitigation and then driven down toward the noise floor after ECA-C. | `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/helperMeasureZeroDopplerSuppression.m`, `BistaticDataAnalysis/mitigateClutter.m`, `BistaticDataAnalysis/createRDM.m` |
| **Session RF Sufficiency Audit** | A session-level pre-detector audit that runs the direct-path precheck across multiple packaged-session parts, checks reference quality, direct-path lag stability, pilot-frequency consistency, and zero-Doppler suppression, then decides whether the capture is sufficient for `aircraft_detection` or the stricter `tracking_validation` goal. | `BistaticDataAnalysis/runSessionRFQualityAudit.m`, `BistaticDataAnalysis/summarizeRFQualityAudit.m`, `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/test_rfQualityAudit.m` |
