# Key Radar Signal Processing Concepts

This document tracks the key concepts introduced during this project and points to the relevant MATLAB files where they are implemented.

| Concept | Description | Implemented In |
| :--- | :--- | :--- |
| **Data Cube** | A 2D matrix structuring raw 1D signal data into `fast-time` (range) and `slow-time` (Doppler) dimensions for radar processing. | `loadIQData.m` |
| **Coherent Processing Interval (CPI) in Passive Radar** | In passive radar, there are no transmitted pulses. The CPI is an **artificial construct** created by segmenting the continuous incoming data stream into fixed-length chunks. Each chunk is treated as a "virtual pulse," allowing for Doppler processing. The length of this artificial CPI is a critical tuning parameter: a longer CPI improves Doppler resolution but can cause smearing for fast targets, while a shorter CPI has worse Doppler resolution but provides a clearer snapshot. | `analyzeBistaticData.m` (see `config.cpi_duration_s`) |
| **ADS-B Triggered Capture Wrapper** | A wrapper-only acquisition path that watches rotated ADS-B files, maintains a rolling track cache, and runs the Phase 1 single-opportunity state machine `watch -> score -> arm -> capture_once -> tail -> exit`. In `shadow` mode it records what it would have done; in `live` mode it calls the existing `runLocalHDTVCapture` wrapper once without changing the manual capture contract. | `TriggerAcquisition/run_adsb_triggered_hdtv_capture.sh`, `TriggerAcquisition/runADSBTriggeredCaptureSession.m`, `TriggerAcquisition/helperTriggerFinalizeCoordinator.m` |
| **Archived ADS-B Evaluation Extension** | A Stage 3C ADS-B prediction checkpoint that inventories the archived truth package, uses MATLAB `gunzip` first with a narrow .NET fallback only for native gzip failures, reuses the frozen Stage 3A versus native `constvel` Stage 3B scoring path, and reports the remaining collection gaps without retraining. | `adsbForTracking/runStage3CArchiveADSBEvaluation.m`, `adsbForTracking/helperBuildStage3CArchiveInventory.m`, `adsbForTracking/helperWriteStage3CReport.m`, `adsbForTracking/helperWriteStage3CFigures.m`, `BistaticDataAnalysis/helperInflateGzipWithDotNet.m` |
| **ADS-B Truth Capture Planning Checkpoint** | A Stage 4A ADS-B prediction checkpoint that prefers the saved Stage 3C artifact and turns archive caveats into MATLAB plots: basic readiness gates, motion/update coverage, frozen MLP versus `constvel` by regime, split coverage, Pi-only versus testing-machine source coverage, receiver-origin metadata coverage, and targeted collection status. The checkpoint preserves the existing truth import path and requires packaged truth plus `session_manifest.json` receiver LLA metadata. | `adsbForTracking/stage4ADSBTruthCapturePlanningLiveScript.m`, `adsbForTracking/helperBuildStage4ADSBTruthCapturePlan.m`, `adsbForTracking/helperPlotStage4ADSBTruthCapturePlan.m` |
| **ADS-B Interval Capture Campaign** | A Stage 4B testing-machine coordinator that SSHes to the Pi for bounded ADS-B-only windows, fetches `*adsb_<session_id>*.txt.gz` truth logs, and packages local `captures/<session_id>/` sessions with `receiver_origin_lla` manifests for Stage 3C/4A validation. | `adsbForTracking/piCaptureCampaign/run_stage4_adsb_interval_campaign.sh`, `adsbForTracking/piCaptureCampaign/README.md`, `adsbForTracking/tests/Stage4BADSBIntervalCampaignScriptTest.m` |
| **Proxy ADS-B Trigger Scoring** | A three-layer ranking scheme for passive-radar capture timing: hard corridor and surveillance-sector gates, geometry-based ENU / boresight / bistatic ranking, and a coarse RF prior seeded from the saved Logan mission report and RF budget. The resulting `trigger_score` is intentionally a proxy confidence score, not calibrated Pd unless a reference-chain penalty is supplied. | `TriggerAcquisition/helperTriggerScoreCandidates.m`, `TriggerAcquisition/helperTriggerResolveAssets.m`, `TriggerAcquisition/helperTriggerUpdateTrackCache.m` |
| **Trigger Candidate Preview Map** | A MATLAB operator/tuning view that evaluates the same trigger geometry on a fixed-altitude ENU slice, converts that slice to a geographic map, and highlights the qualified trigger region while keeping the proxy trigger-score field as background context. The session wrapper can show this preview at watch start and save it as `trigger_candidate_map.png` for later review. | `TriggerAcquisition/plotADSBTriggerCandidateMap.m`, `TriggerAcquisition/helperTriggerRenderCandidateMap.m`, `TriggerAcquisition/helperTriggerEvaluateGeometryField.m`, `TriggerAcquisition/runADSBTriggeredCaptureSession.m` |
| **Phase 1 Trigger Frozen Baseline Validation** | A fixed offline validation set that stages one west-positive replay and one east-decoy replay, compares ranking, qualification, trigger/no-trigger behavior, explicit azimuth-override precedence, empty-region rendering, and preview-footprint deltas against a checked-in Phase 1 baseline, and writes reviewable summary artifacts before any hardware run is approved. | `TriggerAcquisition/runADSBTriggerOfflineValidation.m`, `TriggerAcquisition/helperTriggerPhase1FrozenBaseline.m`, `TriggerAcquisition/helperTriggerWriteValidationScenario.m`, `TriggerAcquisition/ADSBTriggeredCaptureSessionTest.m` |
| **Trigger Path Pre-Hardware Preflight** | An operator-facing readiness gate for the ADS-B trigger path that keeps Pi SSH/logger checks in the shell wrapper, then runs a local MATLAB helper to verify the existing N320 capture wrapper resolves, the frozen mission-report and RF-budget assets load, and the standalone preview can be generated warning-free. | `TriggerAcquisition/run_adsb_triggered_hdtv_capture.sh`, `TriggerAcquisition/runADSBTriggerPreflight.m`, `TriggerAcquisition/adsbTriggeredCapturePhase1DesignSpec.md`, `TriggerAcquisition/TriggerPhase1ValidationLive.m` |

| **Pluto Commissioning Sweep** | A fixed-placement Phase 1 sweep that reuses the proven Stage 6 Pluto-to-USRP smoke path, compares selected tone offsets and amplitudes across repeated runs, writes each run in the standalone artifact schema, and ranks the resulting configurations so one candidate can be taken forward into repeated baseline commissioning. | `TestSetupTesting/runPlutoToneCommissioningSweep.m`, `TestSetupTesting/helperPlutoToneBuildStandaloneResultFromSmoke.m`, `TestSetupTesting/helperPlutoToneDefaultThresholds.m`, `TestSetupTesting/commissionPlutoToneBaseline.m` |
| **Pluto Tone Capture Spectrum Review** | An offline visual diagnostic for saved Pluto-to-USRP `.bb` captures. It reads each dual-channel N320 capture with `comm.BasebandFileReader`, computes centered Welch spectra with `pwelch`, overlays the frozen `SURV = CH1/RX1` and `REF = CH2/RX2` channel convention, marks the expected CW tone offset inferred from the capture name, and writes per-capture spectrum figures plus a summary table of tone margins, frequency errors, and channel-to-channel frequency delta. | `TestSetupTesting/reviewPlutoToneCaptureSpectra.m`, `TestSetupTesting/helperPlutoToneScoreChannel.m`, `captures/plutoSmoke`, `captures/plutoCommissioning` |
| **Pluto Phase 2B Waveform Prototype** | A waveform-selection path that compares the current CW pilot tone against a multitone comb and an LFM chirp, then promotes the multitone comb into the first live-capable smoke experiment. It uses `dsp.SineWave` for tone candidates, `phased.LinearFMWaveform` for the chirp, `phased.MatchedFilter` for pulse-compression and delay-response comparisons, and `pwelch`/`spectrogram`/`goertzel` for spectra and tone-bin integration diagnostics. The live multitone scorer now uses expected-bin comb integration as the primary evidence measurement and keeps nearby-peak search as a diagnostic warning for spurs and channel-frequency agreement. The CPI integration review then treats each 10 ms CPI as an artificial pulse, extracts the complex expected-tone FFT bins, and uses slow-time FFT peak integration plus REF/SURV coherence to show repeatable processing gain across CPIs. The slow-time detector reports both common-bin comb integration and tonewise residual-compensated integration, showing that each tone must be allowed to peak at its own slow-time residual before the comb is summed. The repeatability batch repeats one fixed comb, runs all offline reviews on the FTC, and writes compact summaries suitable for calibration-baseline design. | `TestSetupTesting/designPlutoPhase2BWaveformPrototype.m`, `TestSetupTesting/helperPlutoMultitoneBuildWaveform.m`, `TestSetupTesting/helperPlutoMultitoneScoreCapture.m`, `TestSetupTesting/runPlutoMultitoneStage6Smoke.m`, `TestSetupTesting/reviewPlutoMultitoneCapture.m`, `TestSetupTesting/reviewPlutoMultitoneCpiIntegration.m`, `TestSetupTesting/runPlutoMultitoneSlowTimeDetector.m`, `TestSetupTesting/runPlutoMultitoneRepeatabilityBatch.m`, `TestSetupTesting/PlutoWaveformPlan.md` |
| **Pluto Multitone Calibration Health Check** | A baseline-and-check workflow for periodically validating the Pluto injection and dual-channel N320 receive path before bistatic radar data collection. The baseline wrapper commissions a golden reference from saved captures or a repeatability `batch_summary.csv`, saving waveform settings, hardware settings, thresholds, per-run metrics, baseline medians, and plots. The check wrapper can replay a saved capture or run the live hardware path, then compares expected-bin margins, slow-time peak margins, REF/SURV coherence, and tonewise detector contrast against the golden baseline to produce `PASS`, `WARN`, or `FAIL`. | `TestSetupTesting/runPlutoMultitoneCalibrationBaseline.m`, `TestSetupTesting/runPlutoMultitoneCalibrationCheck.m`, `TestSetupTesting/runPlutoMultitoneRepeatabilityBatch.m`, `TestSetupTesting/reviewPlutoMultitoneCapture.m`, `TestSetupTesting/reviewPlutoMultitoneCpiIntegration.m`, `TestSetupTesting/runPlutoMultitoneSlowTimeDetector.m` |
| **Reference Spectrum and Pilot-Evidence Precheck** | A short-slice diagnostic that confirms the reference channel looks like a usable ATSC illuminator by checking ADC level, spectral flatness, a metadata-anchored pilot PSD line, and whether the resulting reference is sufficient to continue passive-radar analysis. This is especially relevant for passive HDTV because the ATSC pilot is the one narrow, always-transmitted spectral feature that reliably tells us whether the direct-path reference is present at the expected broadcast location. The pass/fail gate is now PSD-first, not coherence-first. | `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/checkRefQuality.m`, `BistaticDataAnalysis/helperMeasureATSCPilotEvidence.m`, `BistaticDataAnalysis/helperMeasurePilotCoherenceProfile.m` |
| **Standalone Pluto Tone Hardware Precheck** | A short hardware-readiness gate that uses a Pluto-driven CW tone before the full passive-radar acquisition pipeline. It loads a commissioned baseline, validates the frozen runtime settings, builds and starts a deterministic Pluto tone, reuses the existing N320 capture path, reads the resulting `.bb` file through the proven `loadIQData` path, scores each N320 channel on tone detect margin, tone frequency error, ADC-relative level, and baseline-relative level drift, then adds a joint channel-frequency consistency check plus advisory-only cross-correlation. It intentionally stays separate from the ATSC direct-path precheck and does not hard-gate on raw channel power ratio or `xcorr` lag. The standalone slice also supports reviewing saved results, commissioning a reusable baseline from prior standalone runs, and failing early with a saved result when the Pluto runtime dependency is missing. | `TestSetupTesting/runPlutoTonePrecheck.m`, `TestSetupTesting/helperPlutoToneLoadBaseline.m`, `TestSetupTesting/helperPlutoToneCompareBaseline.m`, `TestSetupTesting/helperPlutoToneBuildWaveform.m`, `TestSetupTesting/helperPlutoToneStartTx.m`, `TestSetupTesting/helperPlutoToneCaptureN320.m`, `TestSetupTesting/helperPlutoToneReadCapture.m`, `TestSetupTesting/helperPlutoToneScoreChannel.m`, `TestSetupTesting/helperPlutoToneScoreJointMetrics.m`, `TestSetupTesting/helperPlutoTonePlotSummary.m`, `TestSetupTesting/helperPlutoToneWriteArtifacts.m`, `TestSetupTesting/helperPlutoToneLoadResult.m`, `TestSetupTesting/reviewPlutoTonePrecheckResult.m`, `TestSetupTesting/commissionPlutoToneBaseline.m`, `TestSetupTesting/plutoTonePrecheckDesignSpec.md` |
| **ATSC Pilot Evidence Audit** | A pilot-identification step that uses one centered Welch PSD for both plotting and scoring, anchors the expected pilot to the ATSC raster and capture tune frequency, searches the normal-side neighborhood first, keeps mirrored candidates diagnostic-only, and then measures residual pilot stability after frequency centering. In this bistatic passive HDTV workflow that matters because the reference channel drives direct-path lag calibration and ECA-C clutter cancellation, so confirming the real transmitted pilot is more meaningful than rewarding whichever FFT bin happened to stay phase-aligned across CPIs. The old FFT-bin coherence metric remains available only as a legacy diagnostic. | `BistaticDataAnalysis/helperMeasureATSCPilotEvidence.m`, `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/runATSCPilotAuditValidation.m`, `BistaticDataAnalysis/tests/ATSCPilotAuditTest.m` |
| **Direct-Path Lag Dominance Check** | A lag-domain precheck that uses a whitened cross-correlation across multiple CPIs to verify that the surveillance and reference channels share one dominant direct-path delay instead of a flat or ambiguous lag profile. | `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/helperMeasureCrossCorrelationPeak.m` |
| **Zero-Doppler Ridge Suppression Check** | A before/after ECA-C diagnostic that measures whether the direct-path and static-clutter ridge is strong before mitigation and then driven down toward the noise floor after ECA-C. | `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/helperMeasureZeroDopplerSuppression.m`, `BistaticDataAnalysis/mitigateClutter.m`, `BistaticDataAnalysis/createRDM.m` |
| **Session RF Sufficiency Audit** | A session-level pre-detector audit that runs the direct-path precheck across multiple packaged-session parts, checks reference quality, direct-path lag stability, pilot-frequency consistency, and both zero-Doppler suppression depth and residual post-ECA ridge level, then decides whether the capture is sufficient for `aircraft_detection` or the stricter `tracking_validation` goal. It de-emphasizes raw inter-channel power asymmetry when surveillance and reference hardware have intentionally different gain, and it treats a reference-side LNA/preamplifier as a valid hardware adjustment when PSD-based pilot evidence is persistently weak. | `BistaticDataAnalysis/runSessionRFQualityAudit.m`, `BistaticDataAnalysis/summarizeRFQualityAudit.m`, `BistaticDataAnalysis/runDirectPathPrecheck.m`, `BistaticDataAnalysis/test_rfQualityAudit.m` |
